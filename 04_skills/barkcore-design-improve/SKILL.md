# 審美眼：診断・上位3点の修正・比較・再診断

## 適用と読むもの
作業場所のAGENTS.md、案件の目的・対象・ブランド・design-direction.mdを読む。クライアントの指定を優先し、自社の好みを無条件に適用しない。05_winning_feedback/checklists/review.md と06_workflowの該当手順を参考にする。
このスキルで改善を依頼された場合は診断から修正・再診断まで行う。「診断だけ」「比較だけ」という依頼はその範囲に限定する。45項目は[検査視点](references/inspection-45.md)、採点は[採点規則](references/scoring-and-feedback.md)、レポートは[出力仕様](references/report-format.md)。元のdesign-eye-auditorを未インストールでも使えるよう、必要資料をこのフォルダに置く。

## HP・自社サービスの実施位置
HPは候補から1案が選ばれた後、自社サービスはUIUX1案が確認された後に行う。実装前のデザイン案を画像または画面として確認し、このスキルで上位3点を修正・比較・再診断する。結果と修正版を本人に示し、確認後に詳細指示書を整え実装へ進む。全候補を修正しない。案選定や実装のための承認をこの診断で代替しない。
既存制作物の改善を直接依頼された場合は、その制作物を対象として一巡する。実装後の通常の表示・操作チェックは、この実装前の審美眼工程とは別に残す。

## 1. 修正前を保存して診断
実画像を開く、または実サイト・アプリを画面で確認する。コードを読んだだけで見た目を採点しない。URLなら実画面を取得する。画像も閲覧方法もない場合は必要な素材を1つだけ質問する。
案件の目的・相手・媒体・変えられない内容を既存資料から確認。不明は未確認として暫定診断。事実・公開コピーを勝手に補わない。
重複しない `03_outputs/日付_案件_審美眼改善/` にbefore画像、目的、表示幅、ページ位置、表示状態、確認日、素材の版を記録。PCとスマホはそれぞれ別に採点し、合計を混ぜない。
45項目を2/1/0/N/Aで評価し根拠を記録。読めない項目は「未確認」も添え、根拠が取れるまで採点確定しない。N/Aを見えない項目の逃げ道にしない。
良い点を原則3つ以上示す。確認できる良い点が少ない場合は発明せずその理由を書く。
最優先は、理解・可読性→目的との一致→行動への流れ→信頼→細部の順で選ぶ。上位3点を、問題／画像上の根拠／影響／修正箇所／変更案／確認方法で提示。問題が3点未満ならある分だけとし、無理に3つ作らない。

## 2. 上位3点を修正
本依頼の範囲で3点を修正し、診断だけで止まらない。必要な依存変更は行えるが、全面的な別デザインへ拡張しない。良い部分と合意済みのコピー・事実・機能・参考方向を守る。
- HTML/CSS/アプリ等：編集元を確認して実装を修正。元を保つ新しい版で行えるならそちらを優先。既存ファイルを上書きする必要がある場合は、具体的な差分・範囲を用意してAGENTS.mdどおり本人確認を得る。同じ許可範囲内で項目ごとに聞き直さない。
- 画像だけ：元画像を開いてから、利用可能な画像編集・生成ツールで別ファイルへ修正。ラスター画像編集はimagegenスキルと画像編集ツールを使い、元画像を上書きしない。画像だけの編集では元サイトのコードが直ったとは報告しない。
- 素材・ツールが不足：修正指示と再開条件を記録。「修正未実施」と明記し、比較用のafterを捏造しない。
各修正のファイル・対象・理由、対応する指摘IDを記録する。未許可のロゴ・実績・料金を足さない。外部公開や顧客への送信はこのスキルの範囲に含めず本人許可を得る。

## 3. 同じ条件で比較・再診断
afterを実際に開く。Webは同じURL条件・表示幅・倍率・ページ位置・画面状態で撮影。動きのある画面は比較する時点を合わせ、動作も別途確認する。PCとスマホの両方を対象とした場合は両方を確認。
beforeとafterを並べて見られる比較資料を作る。原画像のパス、表示条件を添える。並べた画像やHTMLの比較表示は検証資料であって制作物本体ではない。
3点ごとに「改善／一部改善／未改善／別の問題が発生／未確認」を判定し、見た目の差・根拠・残課題を示す。点数だけで改善と言わない。
修正後も45項目すべてを同じ目的・条件で再診断。変更で別の文字が読めなくなる、スマホが崩れる、操作が壊れる等も確認。N/Aが変わった場合は理由を記録し、分母が違うスコアを単純な改善幅にしない。
一巡（初回診断→3点修正→比較→再診断）を基本にする。今回の修正が原因の新しい崩れは同じ範囲で直し再確認する。元からある別課題は残課題として示し、自動で何巡も拡張しない。上位3点をすべて解消できない場合も未改善の理由を正直に残す。

## 4. 渡すもの
before/after、初回と再診断の45項目レポート、修正対応表、比較資料、修正済み成果物または編集元、残課題、未検証を渡す。元ファイルの保存先と修正版を区別する。
成果は目的・観察根拠で説明し「点数上昇＝売上改善」としない。顧客の反応ではないため05の勝ちパターンへ自動登録しない。共通の学びは本人確認後に記録。

## 共通基礎との照合
診断前に `01_knowledge/06_workflow/design-basics.md` を読む。用途の目的と共通原則を照合する。45項目の採点規則は維持し、UI/UXの操作・状態確認は見た目の点数とは別に記録する。
