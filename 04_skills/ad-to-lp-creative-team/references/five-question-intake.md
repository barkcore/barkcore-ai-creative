# 5つの回答で広告からLPまで制作する

## 受付の正本

案件選択を含む5つの質問すべてを3択で提示し、選ぶだけで目的・対象・価値・CTAを整理して広告3案とレスポンシブLPの制作に入る。自由記述を必須にしない。デザインの専門知識、色や書体の指定、コピー原稿、参考選択は求めない。Harukazeの参考選定と設計はClaude Codeが行う。

開始依頼を確認後、Q1〜Q5を原則1問ずつ提示する。各問に「質問 2/5」のように進捗を付け、選択肢を必ず3つ明示する。Q1はA/B/C、Q2以降は1/2/3で答えられるようにする。Q1の回答に合わせて該当案件を読み、以下の選択肢表を使用する。すでに回答済みの項目は聞き直さず、残りだけ聞く。まとめて答えたい希望には残りを3択付きでまとめて提示し、対応が明確な5回答を一括で受け取った場合はそのまま制作する。

## 制作開始の条件（5問を飛ばさない）

Q1のジャンル選択だけでは制作を開始しない。Q1〜Q5それぞれについて、ユーザーの明示的な回答またはその設問への「おまかせ」が揃っているか確認する。架空案件の設定が詳しくても、Q2〜Q5の回答の代わりにはしない。

ジャンルだけ回答された場合は、その案件の選択肢を使って「質問 2/5」を提示し、回答を待つ。以後も未回答の次の質問を3択で1問ずつ提示する。無回答・時間経過・曖昧な「はい」を選択肢の回答とみなさず、未回答を自動補完して制作へ進まない。「おまかせ」は対象の設問を記録し、他の未回答項目まで回答済みにしない。ただしユーザーが明示的に残り全部を任せた場合は、その対象と採用した選択肢を記録する。

受付中はZIPの確認・展開や該当案件の読み取りまで進めてよいが、広告コピー・デザイン設計・画像生成・LP実装は5回答が揃ってから行う。`brief.md` にQ1〜Q5の回答を記録し、広告とLPへ反映する。既存の会話に明確な回答がある設問だけ聞き直さない。ユーザーから質問省略や手順変更を明示された場合は、その指示を優先する。

## 質問文

1. **何を作りますか？** A：ビジネスセミナー／B：美容／C：子どもの英会話。ご自身の商品があれば、A・B・C以外でも「自分の商品で作りたい」と教えてください。商品名と何の商品かを一言添えてもらえれば進められます。
2. **一番届けたいのは、どんな人ですか？** 下表の3択を必ず添える。
3. **どの悩みと「こうなりたい」に寄り添いますか？** 下表の3択を必ず添える。
4. **この商品のどの価値を、一番伝えますか？** 下表の3択を必ず添える。
5. **LPを見た後、どの行動につなげたいですか？** 下表の3択を必ず添える。

「一つ選んでください。番号だけで大丈夫です。」と案内する。自由記述の問いだけを出したり、候補を単なる例として扱ったりしない。回答なしに勝手に選択しない。ユーザーが自発的に「おまかせ」と言ったら案件設定に合うものを採用して記録する。自発的な自由回答も受け取るが追記を要求しない。質問ごとに別の設問を追加したり、回答後にブランド・予算・色・資料等の追加アンケートへ広げたりしない。

## 自分の商品でも3択

Q1のA/B/Cはそのまま3択にし、選択肢とは別の一文で「ご自身の商品があれば『自分の商品で作りたい』と教えてください」と案内する。自分の商品を希望した人には、Q1で自発的に提供された商品名・一言説明・添付からQ2〜Q5それぞれ3択を作る。自由記述を必須にせず、根拠のない価格・効能・実績を選択肢として創作しない。商品説明がない場合は汎用の確認用コンセプトと明記する。

対象・目的は制作仮説として選べるが、商品の価値は確認済み説明に基づく。判断材料がない場合は「提供内容を分かりやすく伝える／利用場面をイメージしてもらう／検討に必要な情報を整理する」のような訴求方針を選ばせ、具体的な機能や条件を捏造しない。

候補にない答えも尊重する。A/B/Cの設定を超える効能・保証・年齢・有料プラン等は事実として採用せず、回答の意図を設定内のコピーに変換する。Q3の望む変化は願望であり、保証や証明済み効果ではない。Q4は既知の内容で裏づけ、Q5はデモの導線として設計する。

## 5回答から制作に渡す情報

| 回答 | 制作の判断 |
| --- | --- |
| Q1 | 商品・案件、既知の事実、練習/自分の商品ルート |
| Q2 | 広告の呼びかけ、人物/商品の見せ方、LPの読み手 |
| Q3 | 共感のフック、主コピー、LPで受ける悩みと期待 |
| Q4 | 商品を選ぶ理由、補助コピー、本文の確認済み根拠 |
| Q5 | CTA文言、広告→FV→本文→CTAの接続 |

`brief.md` に5回答、確認済み事実、制作仮説、未確認事項を区別して残す。3広告の訴求角度は、同じ対象・価値・目的からClaude Codeが展開する。色や構図だけの違いにしない。

5回答後は認識を短く要約して制作を開始し、必須の「これでよいですか？」や広告1案の承認待ちで止めない。方向性や最初の画像は途中共有できるが、ユーザーから修正がなければ残りの画像・LP・検品へ進む。ユーザーが承認待ちを希望した場合だけ、その指定に従う。

## 不明点を追加質問で増やさない

- A/B/Cの「おまかせ」は提供設定から採用する。自分の商品では回答と添付にある情報から安全な仮説を置き、briefへ記録する。
- 未確認の価格、割引、効能、口コミ、人数、締切は省略。未定価格を勝手に無料にしない。予約・購入の希望はCTAの目的であり、実送信・公開の許可ではない。
- 商品情報が少ない場合も、Q1の説明と回答で分かる範囲の確認用LPを作る。資料の追加提出や価格ヒアリングを必須にしない。
- 実物の写真がない場合はイメージ素材を使い、実商品の正確な写真と偽らない。未確認の情報は納品時の要確認事項に残す。
- 技術的にZIPが読めない、保存先が使えない、生成機能がない等は率直に伝える。追加の実行許可が必要なら停止する。5問という形式のために安全確認を省略したり、未生成を完成と偽ったりしない。
