# 整理した情報を使う、最後のサプライズ

01_brandの初版を保存・確認したら、追加の質問や選択アンケートを出さずにこの工程まで行う。最初の説明や途中のヒアリングではサプライズを予告しない。今回の対象はPC版FV画像1枚。HP全体の実装、公開、商品・顧客ナレッジの構築へ広げない。

## 用途を決める

1. brand_summary.md、company_profile.md、文体・NG・色のルール、source-map.mdを読む。利用目的と今後の目標も確認する。
2. 現在の本人の目標に合う用途を決める。例:事業を知ってもらう目標なら事業のHP、作品や自分を知ってもらう目標ならポートフォリオ、既に活動をしているなら活動紹介。古い目標を現在の希望として扱わない。
3. 目標が未確認、複数で決められない、サイト用途につながらない場合は「ポートフォリオ用」にする。目標・用途・デザインの好みを追加で聞かない。
4. 既に事業がある方でも、本人の目標が作品紹介ならポートフォリオを選べる。準備中の方に架空のサービスや販売導線を作らない。

## サプライズの伝え方

ナレッジの初版が保存できた時点で、簡潔に伝えて生成を始める。
「ここまで整理した情報をもとに、あなたのホームページのファーストビュー画像を1枚つくります。あなたの強みや大切にしたいことが、どんなデザインになるか体験してみましょう。」
用途は「目標に合わせて○○用にしました」、判断できなければ「今回はポートフォリオ用にしました」と説明する。用途を決めた根拠を短く示す。承認や感想を必須の質問にしない。

## コピーとデザイン

- ナレッジから本人らしい主見出し、短い補足コピー、対象の呼び名を組み立てる。目標と文体を優先し、存在しない数字・資格・顧客名・受賞・サービスを足さない。
- これから始める方は学習中・自主制作・今後の方向性を正しく表す。「プロ」「豊富な実績」などに変換しない。未確認の項目は画像に出さない。
- 設定済みの色や書体があれば反映する。なければ価値観や表現の好みからAIが提案として決める。提案した配色・コピーを本人の確定済みブランドルールとして01_brandへ戻さない。
- PC版の横長FVを1枚生成。目安は1920×1080以内の横長、コピー・ビジュアル・余白のある完成カンプ。長文を詰め込まず、見出しは大きく読みやすくする。実装済みHPと誤認させない。
- 顔・ロゴの資料がない場合は本人の顔やロゴを捏造せず、活動に合うイラスト・抽象表現・モチーフを使う。

## 画像生成と保存

出力先は `03_outputs/fv-experience/<重複しない日時名>/`。既存作品を上書きしない。

1. 使用可能な画像生成ツールを確認する。Codexの内蔵画像生成など、現在の環境で利用可能な画像生成を使う。既存の接続済み生成ツールでもよい。特定のAPI・プラグインが全員にある前提にしない。必要な既存ツールの使用手順があれば読む。
2. 本人の情報から作った正確な日本語コピー、用途、画面比率、配色、構図、禁止事項を生成プロンプトへまとめ、実際に画像生成を呼び出す。1つの完成案だけを作る。品質不良なら問題に絞って1回だけ修正できる。案の選択や修正ヒアリングは増やさない。
3. 生成結果を開いて、主見出し・名前の誤字、文字切れ、架空の実績、未確認情報、NG表現がないか確認する。HTML・SVG・文字だけのファイルを生成画像の代用品にしない。
4. 実際の画像をこの出力先へコピーし、`fv.png`（生成形式がJPEGならfv.jpg）として保存する。生成元の保存先だけに置き去りにしない。
5. `design-notes.md` に用途、目標からの判断理由、使った事実と01_brand内の出典位置、コピー、提案として選んだ見せ方、画像生成プロンプト、参照した情報とAIが提案した表現の区別を保存する。
6. `result.json` に `status`（generated / unavailable / failed）、用途、画像の相対パス（成功時だけ）、説明ファイル、試行数を記録する。成功は実画像があり、開いて確認できた場合だけ。再開時にgeneratedで画像が存在すれば再生成せず、画像と説明を再提示する。

画像生成が使えない場合は新しいAPI設定・課金・プラグイン導入や秘密情報の取得を始めない。「情報の整理は完了しました。この環境では画像生成が使えないため、FV画像はまだ生成できていません」と正直に伝える。design-notes.mdに準備済みプロンプトを保存し、result.jsonはunavailable、画像パスはnullにする。使える環境でこのファイルを読めば再開できると案内する。ツール失敗もfailedとして理由を残す。文字の準備だけを画像生成完了として扱わない。

## 最後に渡すもの

成功時は画像を表示し、画像の保存場所と01_brand/brand_summary.mdの場所を伝える。「このコピーには○○という価値観を、この見せ方には○○という強みを使いました」と2〜3点だけ具体的に説明する。ナレッジが制作に役立ったことを伝える。
「これはPC版のFVデザイン画像です。HPの実装・公開はしていません」と用途を明確にする。ほかの5領域は新規なら空、既存なら変更なし。質問台帳をリセットせず、画像工程でも追加質問しない。
