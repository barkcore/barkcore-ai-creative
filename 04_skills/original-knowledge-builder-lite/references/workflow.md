# 進め方と環境の接続

## 同じZIP、2つの入口

### 初めて
解凍したキットの `AI-Creative` を作業場所としてそのまま使う。
別の場所へ作業場所を作る必要はない。Codexが使えるPCを前提とする。まだ使えない場合は、AIアプリを使える状態にしてから再開できることを伝える。このキットからDay1特典や環境セットアップガイドの受け取りへ誘導しない。環境構築・MCP/APIの接続設定はこのキットでは行わない。

### セットアップ済み
既存の `AI-Creative` を作業場所として開く。新しいZIPをその上へ手動でコピーしない。
キット内の `scripts/prepare_workspace.py` を使う場合、先に `--dry-run` で一覧を確認してから `--mode continue --target <既存の絶対パス>` で実行する。
Pythonが使えない場合、同じ規則で不足ディレクトリと新しいスキルだけをコピーする。インストールを必須にしない。
既存のルート指示書、9雛形、プロジェクト、作品、接続設定は変更しない。新しいスキルが同じ場所にあり内容が異なる場合は自動上書きせず、キット側のSKILL.mdを明示して使う。

## 読む順番

1. 明示された作業場所のAGENTS.md / CLAUDE.md（有効なプロジェクト指示）
2. `01_knowledge/01_brand` の既存情報、質問台帳
3. セットアップで作った9雛形のうち、自社・コンセプト・ブランドルール・実績
4. 指定された資料フォルダ内の自社資料

資料の全ファイルを一度に読む必要はない。ファイル名と種類を一覧にし、自社に関連する資料を優先する。
商品・顧客の資料は自社名や事業概要を裏づける箇所だけ利用し、別領域のまとめを作らない。
以前の体験で作った目標は自社情報の利用目的の参考にする。古い仮置きを確定扱いにしない。

## 質問台帳

保存先は `01_knowledge/01_brand/question-ledger.json`。
使用例：
```json
{"version":2,"session_id":"initial-2026-10-06","status":"in_progress","limit":10,"asked":[{"number":1,"topic":"scope","question":"資料を探してよい場所を教えてください。","status":"asked"}]}
```
質問前に台帳を保存し、回答後にstatusをanswered/skippedへ変える。聞き直しは新しいnumberで記録する。使用数はasked配列長。
複数の独立した問いは配列の別レコードとして記録する。`status=completed` は初版を保存・品質確認したときだけ設定する。
既存台帳が壊れている場合は会話から使用済み数を復元する。復元不能なら追加質問せず未確認の初版を出し、履歴が不明な旨を残す。
台帳がないが同じ初回体験の会話が続いている場合も、質問履歴から復元して続ける。

## 保存と報告

構造を短く提示してから作成する。構造承認だけの質問は不要。
既存01_brandがある場合、変更前を03_outputs/knowledge-backupsにバックアップする。他のファイルの上書き許可は拡張解釈しない。
自社概要・ルールを整えたら、質問上限、出典、未確認、他領域の未変更を確認する。
完成報告は「自社・自分の情報の初版ができました。質問はN/10問。入口は01_brand/brand_summary.md。未確認は…」とする。
初回の質問が終わったら、完了確認や感想を追加質問として要求しない。整理した情報で[最後のサプライズ](surprise-fv.md)を実施し、画像と使った情報、次に使う依頼文を渡す。画像を作る用途は目標から判断し、不明ならポートフォリオ。質問を増やさない。

## 質問上限の補助スクリプト
Python 3が使える場合は、スキル内の `scripts/question_budget.py` を使い、質問前の記録と上限を機械的に確認する。
初回の会話で質問をまだしていない場合だけ `init --ledger <台帳の絶対パス>`、質問ごとに `reserve --ledger <台帳の絶対パス> --topic <項目名> --question <1つの質問>` を実行する。`status` は残数確認用。
初回に既に質問した会話がある場合は履歴を復元してから使う。複数の独立した問いは各1回reserveする。Pythonが使えなければ同じ仕様でJSONを保存する。スクリプトが上限・破損・完了済みを返したら、追加質問はしない。

資料を読むときは本人のプロフィール、学習メモ、自主制作の説明も今回の対象に含める。事業の有無を資料から読み取り、SKILL.mdの「対象に合わせた進め方」に合わせる。
