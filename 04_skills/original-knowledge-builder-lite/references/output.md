# 保存仕様

最上位は既存ガイドと同じ `AI-Creative`。6領域は `01_knowledge` の中へ置く。

```text
AI-Creative/
  01_knowledge/
    01_brand/                    ← この体験で整理する
      brand_summary.md           ← 次回の制作AIへ渡す入口
      company_profile.md         ← 名称・概要・理念・ビジョン・強み・沿革・実績
      colors_fonts/rules.md
      ng_rules/rules.md
      tone_voice/rules.md
      source-map.md
      missing-info.md
      question-ledger.json
      change-log.md
    02_product/                  ← 新規ならサブフォルダを含め空
    03_customer/                 ← 同上
    04_assets_references/        ← 同上
    05_winning_feedback/         ← 同上
    06_workflow/                 ← 同上
  02_projects/
  03_outputs/
  04_skills/original-knowledge-builder-lite/
  05_connections/
```

ダウンロード時は01_brandも空の器。構築後、上の9ファイルだけを01_brand内へ出す。
その他5領域にREADME、ダミー、テンプレート、.gitkeep、要確認ファイルを書かない。ZIPのディレクトリエントリで空フォルダを保持する。
既存利用者の他領域は空に戻さず、ファイルを残す。「新規では空、既存はそのまま」が条件。

## brand_summary.md
事業がある方は名称と事業概要、これから始める方は本人の呼び名と現在の取り組み、理念、ビジョン、強み、確認できた実績、文体、視覚ルール、NG、詳細への相対リンクを短くまとめる。
商品詳細・顧客心理・制作物の勝ちパターンを含めない。今回収集していない情報を含む企画を推奨しない。
根拠が薄い項目は未確認と記す。事業紹介文・自己紹介文や文体合わせの入口として使えるが、商品・顧客・導線の設計には追加情報が必要と明記する。

## 共通
文書ごとに対象、更新日、確定/暫定の状態、主な情報源IDを書く。
各事実はsource-map.mdのIDへ対応させる。出典は元のローカルパス、文書内位置やURL、資料日付、ユーザー回答番号。未取得の日付は不明とする。
実績は日付と根拠が分かる範囲だけ記載する。許可不明の顧客名は伏せる。
色コード・フォント・トーンは既存資料または回答だけで決める。未定なら「未確認」と書く。
company_profileには沿革の記述欄を持つが、情報がなければ未確認でよい。無理に追加質問しない。
missing-info.mdには自社情報の不足・矛盾・読めない資料だけを優先順に残す。他領域を埋める質問リストは置かない。
change-log.mdは日時、変更点、理由、出典を記録する。初回の質問台帳を完了後に消さない。

## 既存9雛形からの読み替え
`01_社内情報.md`→概要・理念、`07_コンセプト.md`→価値観・ビジョン、`08_ブランドルール.md`→色・書体・文体・NG、`09_数値・実績.md`→根拠のある実績。
その他は自社の活動を判断する参照資料に留める。元の9雛形は移動・削除・書き換えず、今回の出力先と元資料の位置を完成報告に書く。
複数ブランドを含む場合は対象に合う箇所だけ使う。「ここに書く」、サンプル、未記入欄は未確認。

## これから始める方の保存
ファイル名company_profile.mdは既存互換のため共通だが、本人用の内容は見出しを「自分のプロフィール」にする。本人の概要、これまでの経験・学習、得意なこと、価値観、今後の希望・方向性、表現の好みを記録する。会社情報を捏造しない。
brand_summary.mdは本人のプロフィールと方向性の入口にする。「現在の経験」と「今後の希望」を区別し、自己紹介文に使えることを案内する。
各項目は根拠のある事実・本人の希望・未確認・現時点でなし・未設定・今回は対象外を区別する。確認済みの「なし」や希望をmissing-info.mdの未確認事項に戻さない。これからの方の会社・売上・実績を必須の不足リストにしない。
