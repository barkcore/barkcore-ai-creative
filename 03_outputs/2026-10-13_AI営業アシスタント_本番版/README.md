# 営業アシスタント（本番版・第1段階）

BarkCore自身の営業で使い、使えれば外部提供する、AI営業の自社サービスです。
指示書：`02_projects/AI営業自動化/design-direction.md`（画面は審美眼を通した `after2` のモックが基準）。

## できること（動作確認済み）
- ログイン（メール＋パスワード）。2人で使う。会社（org）ごとにデータが分かれる。
- 会社の追加：CSV読み込み（500社まで・重複と配信停止済みを除外）／1社ずつ追加。
- 追加した会社のサイト（トップ＋会社概要・お知らせ・採用など最大4ページ）をAIが読み、概要・優先度（高/中/低/対象外）・営業する理由・メールに使える事実（出どころURL付き）を作る。
- 営業メールの下書きをAIが作る。人が直せる（自動保存）。「AIにやり直させる」で書き直し。
- 承認：最終確認の画面（宛先・件名・署名つきの本文）→「この内容で送る」。1日の上限、停止中、署名なし、配信停止の案内なし、配信停止済みの相手は承認できない。二重承認もできない。
- 返信を貼り付けると、AIが分類（興味あり・資料希望・打ち合わせ希望・今は不要・営業拒否・自動返信）して、次にすることと返信案を出す。営業拒否は以後送らない相手に登録。
- 設定：1日の上限、メールの最後の文（署名・配信停止の案内）、サービス説明、送信の手動停止。
- PC・スマホ表示、キーボード操作、動きを減らす設定に対応。

## まだできないこと（本番で使う前に必要）
1. **メール送信と返信の自動取り込み**：送信方法が未決定（Zoho／別のメール／他）。いまは承認すると「送信待ち」として保存するだけ。`lib/mailer.ts` に差し込む。
2. 届かなかったメールが3%を超えたら自動停止（送信をつなぐときに実装）。
3. 会社の自動検索（Exa等）。いまはCSVと1社追加のみ。
4. 同じ会社へのフォロー文の自動作成と、フォロー日の管理。
5. 公開する環境の用意（HTTPS・バックアップ・本番のDB）。いまはSQLite（`data/app.db`）で、自分のPCか1台のサーバーで動く前提。他社提供では Postgres へ差し替える（SQLは `lib/db.ts` と `lib/repo.ts` に閉じている）。
6. 特定電子メール法に沿った文面・宛先の取り方の確認、Zohoの利用規約（営業メールの扱い）の確認。

## 使い方（自分のPC）
```bash
npm install
cp .env.example .env        # ANTHROPIC_API_KEY を入れる（中身はチャットやGitに出さない）
npm run create-user -- you@example.com 表示名   # パスワードは画面で聞かれます（10文字以上）
npm run build && npm start   # http://localhost:3200
```
Node 22.13 以上が必要です（`node:sqlite` を使うため、追加のデータベース用ソフトは不要）。

## AIの費用を抑える工夫
調査・採点・返信の分類は `claude-haiku-5-5`、営業文だけ `claude-sonnet-5-5`。`.env` の `MODEL_ANALYZE` / `MODEL_DRAFT` で変えられる。会社のサイトの文章は1ページ6,000字までに切る。同じ会社を二重に調べない。AIの使用量（入力・出力トークン）は `audit` の表に残る。

## 安全のための決まり
- AIは下書きを作るだけ。送るのは必ず人の承認のあと。
- サイトの文章は「材料」として渡し、中の指示には従わない。出どころが読んでいないページの事実は捨てる。
- 社内ネットワーク宛て（localhost・10.x・192.168.x など）のアドレスは読みに行かない。`robots.txt` で禁止されているサイトは読まない。
- ログインは5回失敗で15分待たせる。パスワードは scrypt で保存。
- 秘密情報（APIキー）は `.env` のみ。`.gitignore` で除外。
- `BARKCORE_FAKE_AI` と `BARKCORE_TEST_ALLOW_LOCAL` は**試験用**。本番では設定しない。
