# 見込み4社を契約まで進める計画

作成日：2026-10-13
状態：たたき台。理由は推測なので、まず本人たちに聞いて確かめる。
前提：HP提案は作成済み。数社が見て「いいね」の反応。拒否ではないが、契約には進んでいない。

## 1. 今の状況の読み方（推測。聞いて確認する）
「いいね」で止まる理由は、次のどれかのことが多いです。

| 考えられる理由 | 見分ける方法 |
|---|---|
| 料金が決まっていない・高く感じる | 見積もりを出したか。金額への反応 |
| 今すぐ必要ではない（HPがなくても困らない） | 「いつ頃までに欲しいか」への答え |
| 決める人が別にいる | 誰に相談しているか |
| 次に何をすればいいか分からない | こちらから「次の一歩」を示したか |
| 内容を詰める前で、不安が残っている | 質問や修正の希望が出ているか |

## 2. 次の一歩（会う・連絡するときにやること）
1. **見積もりを出す**（まだなら）。HP 10万円＋フォーム 1万円の仮案を、正式に決めてから出す。
2. **聞く質問は3つだけ**
   - 「この案で進めるとしたら、ほかに決めることはありますか？」
   - 「いつ頃までに公開できると良いですか？」
   - 「決めるのは、どなたですか？」
3. **期日と次の約束を決める**：「○日までにお返事をいただければ、○日に公開できます」。
4. **決めやすい形にする**：HPの契約を、小さく始める選択肢（まず3ページ、ほかは後から）で見せる。

## 3. 契約前に決めておくこと（会社側）
- 正式な料金（HP、フォーム、保守）。仮案のままだと見積もりが出せない。
- 契約書・注文書の形（簡単なものを1枚用意する）。
- 支払い方法と時期（前金・納品後など）。
- 修正の範囲（質問票でまとめて、2回までの仮案）。
- サーバー・ドメインの扱い（お客さんの名義で契約する、がナレッジの方針）。
→ これらは本人が決める。AIは案を出すだけ。

## 4. 4社の管理表（営業の記録）
会社名（社内の呼び名）／担当者／ツテの経路／提案日／見せた反応／見積もり提出日／次の約束日／止まっている理由／メモ。
→ 作る場合は、AIでスプレッドシートの雛形を作ります（外部サービスへの登録は許可をもらってから）。

## 5. 契約になったあとの流れ
注文書 → 質問票で内容を聞く → 仕上げ → 確認 → 公開 → 保守の案内（月5,000円の仮案）。

- HPの契約が決まったあとに案内するのが自然。ただし、先に聞いておくと次が早い。
