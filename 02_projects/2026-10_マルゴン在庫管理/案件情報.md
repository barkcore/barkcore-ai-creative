# マルゴン 在庫管理システム（個別受託・デモ段階）

記録日：2026-10-14　出典：営業（森拓海）からの打ち合わせ共有＋追加回答。AIの解釈は「AIの整理」と書いて区別。
区分：個別業務システム（顧客に案の確認が必要）。料金・納期は未確定。

## 目的
現場の「探す・書き写す・記録する」作業を減らす。目標感は「作業時間を3分の1くらい」（計測はしていない）。
範囲：入庫 → 在庫管理 → 手作業ピッキング → 出荷管理。請求関連は含めない。
現場の担当者が楽だと感じれば、すぐにでも導入したい意向。

## 取り扱い商品
主に、輸入した牛の精液を液体窒素の瓶で保存・出荷。注文は商社が中心、農家への直送もある。
牛の寝床資材・消毒液は、管理対象にするか未確認。

## 現行業務
入庫・出庫の連絡はFAX → 手書きファイルに記録（製品番号・精液の名前・本数・採取日（「再生年月日」と聞いた日付。正式名は要確認）・保管している瓶）。
出庫時は手書きファイルをめくって保管場所を調べ、倉庫で取り出す。出荷内容もFAXで連絡。

## 一番の要望
製品番号を検索 → 「どの瓶に何本あるか」がすぐ分かる。例：瓶Bに30本、瓶Cに20本。ピッキングは人が行う。

## 確認できた条件（2026-10-14回答）
| 項目 | 内容 |
|---|---|
| 採取日 | 同じ製品番号でも採取日が異なる在庫がある |
| 保管場所 | 同じ商品を複数の瓶で保管する可能性あり |
| 場所の表示 | まず瓶の番号で分かる前提 |
| 出荷する在庫の選択 | どの採取日を出すかは現場で選ぶ |
| 瓶の間の移動 | 機能あり・なしの両方で検討 |
| 端末 | 事務所のPCと印刷物。倉庫タブレットは今後検討、初期版は前提にしない |
| 人数 | 作業員は多いときで2〜3人。同時にPCを操作する人数は未確認 |
| 商品数・入出庫件数 | 後日確認 |
| 出荷予定分の確保 | 必要（出荷前に在庫を引き当てる） |

## 管理単位
「製品番号 × 採取日 × 瓶番号」ごとに本数。検索時は製品ごとにまとめて見られる。

## 数の見せ方
- 在庫数：出庫確定前の、保管中の本数
- 引当数：出荷予定として確保している本数
- 引当可能数：在庫数 − 引当数（例：在庫30・引当10 → 別の出荷に使えるのは20）

## 出荷の流れ
1. 製品番号などで検索 → 2. 現場で採取日・瓶・本数を選ぶ → 3. 出荷予定として保存し引当
→ 4. ピッキング表（瓶番号・商品・採取日・本数）を印刷 → 5. 倉庫で取り出す
→ 6. 事務所PCで出庫確定（在庫と引当を減らす） → 7. 出荷連絡用PDFを作成・印刷
PDFを作った時点では在庫を減らさない（出庫確定時に減らす）。

## 引当のルール
- 取消：引当を解除。数量・採取日・瓶の変更：引当も更新。
- 重複して確保しない。在庫以上を引き当てない。

## 瓶の間の移動：2案
- 移動機能なし：通常操作にしない。必要になったときの訂正方法は決めておく。
- 移動機能あり：移動元・移動先・本数を指定。商品全体の在庫は変えず、瓶ごとを更新し履歴を残す。
- 未決：引当済みの在庫を移動できるか／移動時の引当先・印刷済みピッキング表の扱い。

## PDF読取り・初期在庫（以前の共有どおり）
FAX/手書き在庫表のPDF → 読取り → 候補を確認・修正 → 確定。製品番号・本数・日付・瓶の記号は確認できるように。同じPDFの二重登録を防ぐ。
手書きファイルは入出庫の履歴なので、導入時点の残数を確認して初期在庫を作る。読めない所は手入力。手書きの読取り精度は実物で検証が必要（未検証）。

## 未確認
同時操作人数／商品数・瓶数・1日の入出庫件数／資材・消毒液の扱い／採取日の正式名／タンク・区画の要否（今は瓶番号のみ）／出荷FAXの様式／実物サンプル（入庫FAX・手書き在庫表・出荷FAX）／料金・納期。

## 次にしたいこと
「製品番号を検索 → 瓶と本数が出る → 出荷する商品を選ぶ → PDFにする」までのデモを現場の方に触ってもらう。
