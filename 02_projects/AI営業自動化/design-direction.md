## 1. 目的・使う人・印象・主役
- 目的：営業先探し→調査→採点→営業文→承認して送信→返信確認→次の行動を、2人（森ゆづき・森拓海）が毎朝短時間で進める。まず自社利用、使えれば他社に提供。
- 端末：PC中心、スマホは「今日」の確認・承認・返信確認ができること。
- 印象：頼もしさ第一、技術への期待感は第二（ブランド方針）。やさしい言葉、専門語なし。
- 主役：「今日」画面では返信→承認→フォローの3つの塊。「承認」画面では営業メールの下書き全文。
- 確定した決定：送る前に必ず人が承認する（自動送信は将来の別モード）。ボタン名は「承認」。

## 3. 構成と配置（PC幅1280基準、中身の最大幅1120px、左右32px）
| 画面 | 役割 | 配置 |
|---|---|---|
| 今日 | 今日やること | 見出し→3つの塊（返信・承認・フォロー）→「会社を追加する」。塊の中は行（会社名＋理由｜右に操作） |
| 承認 | 1社を確認して送る | 左5:右7、間64px。左＝この会社／営業する理由／メールに使った事実と出どころ。右＝件名・本文・操作 |
| 返信 | 返信の分類と返信案 | 左5:右7。左＝届いた返信・分類・次にすること。右＝返信の下書き |
| 会社の追加 | 条件の文章・CSV・1社追加 | 左右2列（文章で探す｜CSV・1社） |
| 設定 | 営業用ボックス・上限・自動停止・署名 | 1列の設定行 |
共通：ヘッダー（名称、メニュー5つ、右端に「本日の送信 n / 上限通・届かなかったメール n件」）。スマホは下タブ5つ（今日・承認・返信・追加・設定）。

## 4. 文字
書体：Hiragino Sans／Noto Sans JP／Yu Gothic／Meiryo（システム書体。自社HPの書体とは別で、案件固有の指定なし）。1系統のみ。
| 用途 | PC | スマホ | 太さ | 行間 |
|---|---|---|---|---|
| 画面の見出し h1 | 28px | 24px | 700 | 1.4 |
| 塊の見出し h2 | 19px | 同 | 700 | 1.75 |
| 小見出し（承認・返信の左右） | 17px | 同 | 700 | 1.75 |
| 本文・ボタン・入力 | 16px | 16px | 400／ボタン700 | 1.75（本文欄1.8） |
| 補助文・理由・ヒント | 15px／14px | 同 | 400 | 1.75 |
折り返し：`line-break:strict`、`word-break:auto-phrase`、`text-wrap:pretty`。時間「1時間前」などの数字＋単位は改行させない（`.nw`）。
確定文言：「今日やること」「返信が来ています」「承認する」「承認して送る」「AIにやり直させる」「見送る」「内容を見る」「フォロー文を作る」「会社を追加する」「届かなかったメール」。用語は「会社」「承認」に統一（「営業先」「エラー返し」は使わない）。

## 6. 余白・部品の共通値
- 塊の間64px、塊内の行の上下16px、行は上に1pxの線のみ（枠・カード・影は使わない。入力欄・ボタン・ダイアログだけ囲む）。
- 角：ボタン・入力6px、通知6px、ダイアログ8px。ダイアログの影は1つだけ。
- ボタン：高さ44px以上。主役（塗り）は各塊で1つだけ。ほかは薄い枠線（#A9BAB8）の文字操作、ホバーで背景#E6EEED＋枠が主色。補助は下線の文字（見送るなど）。
- 本文欄：最小高さ26em、内容に合わせて自動で伸ばす（欄内でスクロールさせない）。件名・本文は入力と同時に自動保存。
- スマホ：左右16px、塊の中の操作ボタンは幅いっぱい、承認画面は縦1列（会社→理由→出どころ→下書き→操作）。

## 7. 動き
- 非ユーザー起点の動きは使わない。入るのは「調べています」の回転表示（1秒で1周）と、送信ボタンを押したあとの「送信中…」のみ。
- ページのスクロールは止めない。動きを減らす設定では回転を止め、静的な表示に切り替える。

## 8. PC・スマホの違い
PCは左右2列で理由と下書きを同時に見る。スマホは1列、下タブ。右上の本日の送信数は見出しの下に左揃えで表示。タブはタップ範囲56px。

## 9. 状態・操作の流れ（サービスUI）
流れ：今日 → 承認（下書きを読む・直す）→「承認して送る」→ 最終確認ダイアログ（宛先・件名・本文）→「この内容で送る」→「送りました。次は〇〇です」→ 次の会社。ダイアログでは「もどって直す」で戻れる。
| 状態 | 表示と動き |
|---|---|
| 通常 | 3つの塊 |
| 空 | 各塊に「いまはありません」。承認の空には「会社を追加すると、AIが調べて下書きを作ります」 |
| 調査中 | 琥珀の通知「調べています（約1分）」。承認は押せず、ほかの会社は見られる。本文欄は入力不可 |
| サイトが読めない | 赤の通知。承認不可。「手で情報を入れる」「見送る」 |
| 連絡先なし | 琥珀の通知。承認不可。フォーム・電話の候補に回す（将来） |
| 送信中 | ボタン無効＋「送信中…」。二重送信しない |
| 送信失敗 | 赤の通知「送れませんでした」＋原因。内容は残り、もう一度送れる |
| 送信後 | 緑の通知「送りました」。承認ボタンは無効化 |
| 上限到達 | 琥珀の通知。承認の一覧ボタンは「内容を見る」に変わる |
| 自動停止 | 赤の通知（理由と再開方法）。承認の一覧ボタンは「内容を見る」。右上は「送信は停止中です」 |
| 返信 | 分類を選び直せる。「営業拒否」にした会社には以後送らない |
| 保存 | 「保存しています…」→「保存しました。」 |
戻る：全画面に「← 今日にもどる」。訂正：下書きは編集可、「AIにやり直させる」で再作成、「見送る」で一覧から外す。

## 10. 実装方針（本番）
- 構成：Next.js＋Postgres（Supabase等の無料枠から）、定期ジョブ（日次の調査・採点、返信の取り込み）、Claude API、メール送信は自社ドメインのZoho（営業専用ボックス、SMTP送信／IMAP受信）。
- 費用を抑える：検索APIは後付け（まずCSV・1社追加・公開サイト読み取り）。調査・採点は安いモデル、文面だけ上位モデル。同じ会社を再調査しない。
- 会社（テナント）ごとにデータを分ける。他社提供時は提供の合意・料金・利用規約を別途決める（未決定）。
- 送信の安全：専用ボックス、1日5〜10通から、届かなかったメールが全体の3%超で自動停止、配信停止の希望は1回で止める、署名（会社名・連絡先・配信停止案内）必須、承認なしの送信禁止、送信ログ保存。
- 秘密情報：APIキー・メールの認証情報は `.env` と実行環境の秘密設定のみ。リポジトリ・チャット・画面に出さない。
- 認証：2人のログイン（メール＋パスワードまたはマジックリンク）。誰でも開ける状態で公開しない。
- 外部への送信・公開は、実行前に内容を見せて許可をもらう（AGENTS.md）。
