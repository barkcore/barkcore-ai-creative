# 品質スキルの自動呼び出し表

対象：HP・LP・自社サービス・アプリのUI制作（実装まで行うとき）
このファイルが「どの場面で、どのスキルを自動で読むか」の正本。各SKILLにはここへの参照だけを書く。

## 基本ルール
- 下の表の場面になったら、依頼されなくてもAIが自分でSKILL.mdを読んで使う。使ったスキル名は完了報告に書く。
- 優先順位は ①案件の指示書・お客さんのブランド → ②AGENTS.mdと01_knowledge → ③各スキル。スキルの一般論で案件の決定を覆さない。
- 修正は「見た目の品質を上げる範囲」まで。合意済みのコピー・事実・機能・参考方向は変えない。既存ファイルの上書きはAGENTS.mdどおり確認する。
- 実際に画面を開いて確認できないときは、「未実施」と書く。コードを読んだだけで合格にしない。

## 場面ごとの呼び出し
| 場面 | 自動で読むスキル | 使い方 |
|---|---|---|
| 設計前（トークン・色・文字・レイアウト案を作る） | `04_skills/frontend-design/SKILL.md` | 設計メモ作成→「どのページにもある定番」になっていないか自己点検。案件の指定があれば指定が勝つ |
| デザイン案が決まった後・実装前 | `04_skills/barkcore-design-improve/SKILL.md` | 既存ルール通り（45項目診断→上位3点修正→前後比較→再診断）。本人確認後に実装へ |
| 実装中（コードを書いた直後） | `04_skills/baseline-ui/SKILL.md` | 余白・階層・文字・小さな崩れの掃除。ただしTailwind/React前提の項目は、案件がその技術のときだけ適用 |
| 動きを入れたとき（スクロール連動・アニメ・ぼかし） | `04_skills/fixing-motion-performance/SKILL.md` | カクつき・レイアウトのガタつきを確認して直す。動きは案件が求めた分だけ |
| ボタン・フォーム・ダイアログ・メニューがあるとき | `04_skills/fixing-accessibility/SKILL.md` | キーボード操作・フォーカス・ラベル・コントラスト・エラー表示を確認して直す |
| 実装後の最終確認 | 上の「baseline-ui」「fixing-accessibility」（動きがあれば「fixing-motion-performance」も）＋ `05_winning_feedback/checklists/review.md` | PC・スマホの実画面で確認。結果を報告に残す |

## 作業の流れに混ぜる位置（HP・LP・サービスデモ共通）
1. 設計：design-basics.md → visual-quality.md → **frontend-design**
2. 案の選択・確認
3. 実装前：**barkcore-design-improve**（本人確認を挟む）
4. 実装：トップ（または主要画面）を作る
5. 実装直後：**baseline-ui** →（動きがあれば）**fixing-motion-performance** →（操作部品があれば）**fixing-accessibility**
6. 実画面確認（PC・スマホ）＋ review.md
7. 報告：使ったスキル・直した点・未実施の点を書く

## 対象外
- 広告バナー単体など、HTMLを実装しない制作ではステップ5は行わない（広告→LPのLP実装部分には適用する）。
- 本番の法令適合（WCAG認定など）を保証しない。「確認した範囲」を報告する。
